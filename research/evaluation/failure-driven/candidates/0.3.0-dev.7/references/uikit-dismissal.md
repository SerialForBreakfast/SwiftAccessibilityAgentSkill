Treat the controller's dismissal request and successful dismissal completion as different events. Wire each supported completion path to the same presentation owner; a cancelled transition leaves it active. Capture the owner's identity at installation. On completion discard stale/duplicate owners, consume the matching pending state, and resolve eligible targets in the current model, not by the old index.

Separate deciding from dispatching: return the optional target from the mutating transition, end that access, then invoke the external requester. If it presents another panel synchronously, nothing from the old completion may clear that new state. Check by having the requester open another panel, then delivering the old completion again. This proves the app's request path, not focus delivery.
