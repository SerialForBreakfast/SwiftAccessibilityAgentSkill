Close changes presentation state; it does not mean dismissal finished. Have the presenter handle completion (for example, the sheet's onDismiss), including interactive dismissal. Associate the callback with that presentation's immutable identity, not a lookup of whichever panel is active now. If the presentation API cannot distinguish overlapping callbacks, serialize presentations until completion.

At completion, reject an obsolete or consumed owner; consume it before calling out. Resolve the original item's stable ID against the current data and current eligibility. Use the product's eligible fallback or request nothing. Cancellation that leaves the panel open is not completion. An AccessibilityFocusState write requests focus; a unit can assert the target and count, not delivery. Exercise a second panel opening and an old completion arriving after it.
