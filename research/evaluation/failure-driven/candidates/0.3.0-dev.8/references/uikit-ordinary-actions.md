If Open and Delete are independent buttons inside a row, keep their ordinary accessibility paths and wire both buttons to the application. A named shortcut can call the same operation; it is not the only way to invoke it. Do not turn their containing row into a single accessible leaf and assume the buttons remain independently reachable. Group descriptive siblings separately. If using explicit accessibilityElements, include the intended controls in order.

Trace an activation after reuse: button -> installed target or UIAction -> enabled check -> current file -> one callback. Either replace old per-file handlers and reject stale invocations, or install one stable current-owner dispatcher. Do not install both. Invoking a helper directly proves neither button wiring nor accessible navigation.
