# Native replay: 40 persistent whole-task failures

[All 40 pairs](CASES.md) | [first-attempt and adjudication ledger](evidence.json)

This is a retrospective of the exact Gemini signal-v2 first answers, not an evaluation of a new candidate. Every row had a whole-task **fail in both arms** in the sealed source review. A narrow native pass does not reverse that judgment: a correct helper can coexist with a faulty view callback, an unnecessary rewrite, or an ineffective test. Conversely a failed historical test can reflect an incompatible helper interface. The board reports that separately.

## Findings that change a decision

Across 80 implementation lanes, 28 passed native assertions, 18 failed them, 10 failed to compile, 20 compiled without a behavioral verdict, and four remained source-only or unbound. Across 80 proof lanes, 36 passed, five failed assertions, five failed to compile, four were blocked by the subject build, six were built only for offline safety, one lacked its required fixture, and 23 had no executable proof or were source-only. **Eight passing proofs accompanied a failing native contract.**

On the 21 pairs with executed behavioral verdicts in both arms: 11 passed both, six failed both, two improved and two regressed. These are case-level results on the *tested requirement*, not full-task rescues or a population-level estimate. Beyond the wrapper regression below, the other regression was P-852a: a retired tvOS results button selected a rebound item.

- **Async validation, iOS and tvOS:** the native-field assertion submitted a request, changed the live field, then delivered the old response. Both arms accepted it when acceptance should have stayed at zero. The installed answers' own tests passed. Exercise the same mutation path as ordinary typing, not only an edit helper that cancels pending work.
- **Player selection, iOS and tvOS:** both answers on each actual-player-write question changed the local ID but failed the native selection check. We loaded an actual local caption group, started from Off, supplied a distinct offered choice, drove the submitted choice method and read back the real item's selection. A nil readback after a successful local selection establishes the gap without assuming anything about playback or VoiceOver. This is a choice-method probe, not rendered picker interaction.
- **Wrapper ownership:** retaining the installed UIAction across reconfiguration and sending it after B becomes current exposes two tvOS gains (P-7766, P-a00e), one iOS regression (P-7d8c), and one paired pass (P-7622). The ordinary action and teardown paths are checked separately. The critical distinction is which generation the installed registration uses, not whether a separate helper rejects an explicitly stale token.
- **Reused Delete:** the unaided shortcut accepted an invocation after a different file took ownership. The installed shortcut rejected that stale owner but still accepted an old shortcut after permission was revoked on the *same* file. Require both owner and current authorization. A single Boolean grade obscures the difference.
- **Focus:** both AppKit refusal cases' arms on P-be25 failed to try the fallback when a still-attached target refused the request. In the two previously studied iOS dismissal cases, the installed implementations again failed (hidden background/unattached Apply; eligible origin lost), despite green submitted tests. The unexposed SwiftUI onDismiss delivery remains outside the native assertion.
- **No-change controls:** both implementations passed the frozen ListeningSettings binding/range/step/readout oracle on P-e505. That demonstrates the state/write contract, not that a replacement accessibility element is needed, or that it reports the same value through VoiceOver.
- **Evidence quality:** on macOS, the installed ordinary Save implementation passed the original dispatch check, yet its submitted proof called a nonexistent accessibilityPerformPressAction on NSAccessibilityCustomAction. Conversely, a missing test_media bundle resource is a fixture gap, not a negative determination about the metadata predicate.

## What was executed

- The filter is exactly `transitions[*].transitions.whole == "persistent"` in the checksum-pinned return. There are 40 unique IDs, both arms, 19 pairs with a named assertion, and 21 with a source/rubric or other contract. A separately linked executable slider oracle was recovered even though its assertion list was empty.
- The contract lane stages accepted no-change recommendations against the exact supplied starter, selects identified integrated implementation fences, or inserts authored declarations/patches in their supplied context. Selection rules are in stage.py and followup.py. Explanatory quotations and optional alternate products are not concatenated. A retained starter's pass is not evidence an optional rewrite passes.
- Named assertions and minimal local helpers are selected from their original repository packages. The ledger pins the source file and selected method. Additional narrowly scoped probes use the task's own requirement where the reference helper cannot be called, or the source rubric alone cannot establish native behavior. See the individual attempt's selection and contract source hash.
- The proof lane runs submitted Swift test fences against the same staged subject, separately from the controller. Framework imports, XCTest wrappers for free test functions, the answer's testable module name and intact starter declarations are allowed host scaffolding. No correction of a subject API, callback, assertion or expected value. Identical subject compile errors can block a proof without a second redundant compilation. A proposed prose check is not an executed proof; evidence outside native unit scope retains its source grade.
- SDK 27.0 with deployment target 26.0; iOS/tvOS simulators 26.5 and macOS 27.0. All execution was local. Remote-URL proofs were conservatively limited to build-for-testing. No URLs were substituted. No UI automation, model generation, regrading by another model, quota, release edits, or promotion.

## First failures and limits

Raw answers, questions, all staged Swift, intents, native logs, xcresults, first diagnostics and adapter receipts are in the git-ignored evals/results/persistent-replay tree. Public artifacts contain digests and bounded controller diagnostics, not wholesale model answers.

1. tmp6xijam9k: all 80 first cells. The orchestrator was stopped before remote-URL proofs; the interrupted AppKit build itself logged success. Its original disposition is retained alongside the later runtime check. No finished result was overwritten.
2. adapters-o1xp27st: resolved code integration and missing host imports, used the linked frozen slider test, and exercised original file-row, AppKit Save and native media contracts. Compiler success after adding only an import is a host correction, not a model fix.
3. registrations-tg6h920p: first installed-UIAction adapter did not compile: the Objective-C iterator's five parameters import as four in Swift. These eight diagnostics belong to the oracle, not either subject. See the retained first adapter source in that private directory.
4. registrations-nch3vflc: corrected only the iterator host, ran the same implementations through the installed action and ordinary controls, and reinstated Swift Testing imports or supplied starter declarations for three proof hosts.

Use `python3 -B report.py --check` from this directory to verify the evidence host's pinned packets, inputs, logs and report. For a fresh batch, stage.py creates a unique private staging directory; native.py takes its basename. Follow-up builders point at this recorded cohort to avoid silently substituting later artifacts. Build-only, missing fixtures, absent proofs and source-only dispositions are not passes. These inspected cases are development evidence, not holdouts.
