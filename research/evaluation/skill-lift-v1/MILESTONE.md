# Skill-lift milestone design

Status: offline preparation only. Live allocation is zero; no provider setup, worker
message, model run, installation, native example execution or promotion is authorized.

## Comparison contract

Freeze original task inputs, model identity, harness/tool configuration, grading
revision, OS/SDK environment and sampling settings. Candidate context is the intended
variable. Pair the same scenario and preserve every first attempt. Record unavailable
model revisions and token accounting explicitly; unknown identity is not silently
substituted. Do not pool different models, graders or token conventions.

Keep the existing C0 generic, C1 instructions without references, C2 controlled
reference injection and C3 actual instrumented lookup conditions distinct. Condition
coverage does not mean every condition must run for every task. Freeze one coherent
selection and its limits before approval; do not multiply the matrix automatically.
No live provider or invocation command is included in this tranche.

The primary quality metric is a 0–1 normalized rubric score with its conversion from
the existing grading scale frozen before results. Task pass/fail transitions are
reported separately. Missing and inconclusive outcomes remain visible. Sample
uncertainty by scenario family, not paraphrases/platform variants/repeated attempts.
A narrow bootstrap interval on this selection is not universal generalization.

## Gates retained

- Packaging and reference-integrity checks pass.
- No new critical hidden-action, navigation, invented-API or availability defect.
- Paired quality interval supports a non-inferiority margin of 0.02.
- Every affected platform receives explicit regression review.
- Held-out cases stay held out until the candidate and rubric are frozen.
- Independent grading/oracle review passes.
- Claim improvement only with a positive paired interval; otherwise inconclusive.
- Focused-task efficiency targets 15% lower median actual input tokens while quality
  gates pass. Bytes are an offline structural measure, not token telemetry.

All reported gate inputs require actual supporting artifacts and owner-approved
promotion. Numeric gate calculations are not permission to publish a release or run
models. Frontier coding agents remain the target; local-model results are diagnostic.

## Three separate questions

1. Activation: was the skill selected for a relevant request? Test realistic positives,
   near misses and ambiguous requests. Pre-injected context is not automatic discovery.
2. Retrieval: which files were actually read/supplied? Use captured traces/content
   hashes. A ROUTING line or offline metadata lookup is not autonomous retrieval.
3. Usefulness: did the answer satisfy the task without breaking working behavior?
   Accept alternative correct references/implementations; exact-route matching is
   not a stand-in for quality. Grade protocol separately; C0 has no branding penalty.

## Distillation after a useful milestone

Keep the comprehensive research corpus. Distill runtime material only after it has
shown useful outcomes. Hold the candidate fixed, then select a small number of
failure-relevant note-removal experiments, not an eight-way automatic search on all
cases. Match the scenario/provider/harness/rubric and disclose any altered retrieval
conditions. Measure quality, failures introduced and full context cost together.

Offline pruning may remove duplicate instructions or identify large references,
but cannot establish that deleting a note preserves model behavior. GEPA-style
reflection can inspire generalization from failures; automatic prompt optimization
still consumes model calls and is not enabled under the present zero-run boundary.
