# Authoring and capture record

The owner selected all three platforms and requested implementation of the plan
"SwiftUI Failure-Driven Unit-Test Campaign": all 15 guidelines, a consolidated
checkpoint, real modifier compilation, focused observable contracts, original
failure preservation, paired developer questions/rubrics, and no UI tests, mandatory
manual checks, paid dependencies, new model runs or changes to released/frozen inputs.

This is a summary of the visible request, not a claimed exact full-provider transcript.
The complete visible plan is retained in OWNER-REQUEST.md. Provider-internal context
and any unavailable historical prompts remain unavailable; they are not reconstructed.

## Captured outputs and provenance

- Exact synthetic subject questions, complete task inputs, controller rubrics and
  empty independent-answer arrays are in prompt-records.json. These are newly
  authored development tasks, not held-out prompts or independently answered gold.
- Swift source, test source and intended mutants are hashed in platform manifests.
- Every native attempt snapshots exact listed inputs, adapters, command, environment,
  output diagnostics and outcome before repairs. The first Mac compile checks the
  initial 52-method source set; the expanded source set adds native coordinator tests.
- Compile checks use the existing adapters' default Swift language mode; generated
  package unit builds use Swift tools 6.0. Compiler version is recorded separately.
- Authoring code and any actual errors are outputs of this development session,
  not evidence of a controlled model ranking. Shared algorithms across platforms
  do not create independent behavioral families.
- Controller-only record: do not load incidents, solutions, rubrics or all examples
  into a future subject's context.

Raw logs/source snapshots stay private in the archive referenced by the final
receipt. Sanitized excerpts and separate analysis explain actual failures and repairs.
