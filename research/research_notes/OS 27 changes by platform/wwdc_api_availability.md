# WWDC26 accessibility sessions and OS 27 accessibility API availability (snapshot 2026-11-05)

Method note (applies to all sections):
- Sessions: I pulled the WWDC26 listing at https://developer.apple.com/videos/wwdc2026/ (138 session IDs) and downloaded every session page at `https://developer.apple.com/videos/play/wwdc2026/NNN/`. I then ranked all 138 transcripts by keyword hits (accessib, VoiceOver, caption, subtitle, Dynamic Type, Larger Text, rotor, Voice Control, Switch Control, assistive, braille, interpreter, and similar). Timestamps are the transcript's own `data-start` values, shown as m:ss.
- Symbols: I read DocC JSON at `https://developer.apple.com/tutorials/data/documentation/<path>.json`, field `metadata.platforms[]` (`introducedAt`, `deprecatedAt`, `beta`, `renamed`). I also scanned the DocC navigator indexes (`https://developer.apple.com/tutorials/data/index/{swiftui,uikit,appkit,accessibility,mediaaccessibility,avkit,avfoundation,xcuiautomation,livecommunicationkit,translation,pencilkit}`). For each module I fetched every symbol whose path matched accessibility, caption, legible, subtitle, content-size, Dynamic Type, rotor, direct-touch or braille: 2,518 symbols in the five UI and accessibility modules, plus targeted scans of the others. Then I filtered for introducedAt 26.1 or later, or deprecatedAt 26.1 or later.
- "?" in a platform list means the JSON has a platform entry with no `introducedAt` value. This is common for older UIKit symbols on tvOS.
- Evidence tiers. **T1** is a verbatim Apple primary-source field or a timestamped transcript statement. **T2** is an Apple primary source that is informal or indirect, such as a lab Q&A remark, an on-screen code sample, or a listing category. **T3** is my inference from T1/T2.
- Earlier passes API-01..05: the notes directory held no prior files at snapshot time (`research_notes/OS 27 changes by platform/` was empty), so I could not reconcile against them. Each record below flags the likely topic matches ("possible match to earlier API-0x") so the writer can check.

## Which WWDC26 sessions cover accessibility, and what does each claim is NEW in 27 versus established technique?

### Takeaway
WWDC26 has four dedicated accessibility developer sessions: 219 (reading content), 220 (custom controls), 221 (tvOS Dynamic Type / Large Text) and 256 (generated subtitles and subtitle style preview). There is also the Accessibility Technologies Group Lab (8005). The WWDC26 catalog has no "What's new in Accessibility", "What's new in UIKit" or "What's new in AppKit" session. The UIKit and AppKit slots are "Modernize your UIKit app" (278) and "Modernize your AppKit app" (289), and these two plus "What's new in SwiftUI" (269) contain essentially no accessibility content. Most of what 219 and 220 present is established API (iOS 5–18) being revisited. The genuinely "27" items are behavioral: SwiftUI `accessibilityLinkedGroup` gains text-navigation linking, tvOS gets Large Text, subtitles are generated on-device, and macOS gains "show borders". The main new API surfaces show up in sessions 230 (assessment accessibility toggles) and 256 (whose subtitle-preview APIs actually shipped in 26.4).

### Inferences
- [T3] For corpus labelling: 219 and 220 are "revisit" sessions. The only 27-specific developer claim in them is the `accessibilityLinkedGroup` behavior extension (WWDC-107). 221 and 256 announce system features whose adoption mostly uses existing API. Sessions 230 and 285, plus the XCUIAutomation VoiceOver service, carry genuinely new accessibility-relevant symbols.
- [T3] An agent should not emit "new in iOS 27" for `causesPageTurn`, `editCategory`, text navigation elements, `accessibilityDirectTouch` or `AccessibilityNotification` merely because WWDC26 demonstrated them.

## For each symbol, what is the introducedAt per platform from DocC JSON (new in 27 vs older symbol whose behavior changed)?

### Takeaway
DocC confirms that almost every symbol demonstrated in 219 and 220 predates 27 (iOS 5–18). The genuinely new accessibility-relevant symbols in the 27 SDKs are:
- AccessibilitySettings `isApplicationAccessibilityEnabled` and its change notification/message
- `AXSpeechAttributeSSML`
- `MACaptionAppearanceDomain.videoConferencing`
- `AVMediaCharacteristic.signLanguageInterpretationForAccessibility` (27.1)
- `XCUIVoiceOverService`
- AVKit `AVPlaybackUserInterface…` legible options
- the macOS assessment accessibility toggles
- SwiftUI `TabsPickerStyle` / `.tabs`
- PencilKit `PKStrokeRecognizer`

There are no new `AccessibilityTraits`, `UIAccessibilityTraits`, `AccessibilityNotification` cases, rotor APIs or NSAccessibility symbols in 27. The 26.1–26.4 point releases added more than 27.0 did, including the subtitle-preview APIs that WWDC26 session 256 presents. There is a large SwiftUI deprecation wave at 27.3 (`ContentSizeCategory` and the legacy `.accessibility(label:)`-style modifiers).
