# Blind grading audit of the first Gemini baseline

**Ten of the 14 originally flagged primary gaps held up.** Among 34 originally failed preservation answers, 26 met the primary behavior on review. Twenty of the 34 had unnecessary changes as the main concern. One sampled pass also missed its primary behavior. This is a versioned second opinion on selected answers. The frozen first ledger still reports 263/384 passes.

| Selected first grades | Cases | Blind whole pass | Blind whole fail | Blind primary pass | Blind primary fail |
|---|---:|---:|---:|---:|---:|
| Preservation failures | 34 | 4 | 30 | 26 | 8 |
| Registered primary failures | 14 | 3 | 11 | 4 | 10 |
| Sample of passes | 12 | 11 | 1 | 11 | 1 |

Three Codex reviewers each independently reviewed one shuffled shard of 20 answers with a fresh conversation. They saw the question, full answer, the named decision, and the linked criterion or unit examples. Original verdicts, selection stratum, case identifiers and first-grader rationale were withheld. The coordinator who knew the baseline selected and joined the cases. Each answer received one new judgment. Sampled passes were drawn without replacement from six preservation, four repair and two workflow cases, using a fixed seed derived from `gemini-stage-a-blind-audit-v1`. The sample covers the three audited lanes. It cannot estimate the grading error rate across the portfolio. All 60 input and answer hashes and all 60 exact quotations were checked against the source records. No Gemini generation or native execution took place. The packets were briefly staged outside the project during preparation and relocated to the project's private evaluation directory.

## Which gaps merit skill content?

| Priority | Cases in this audit | Smallest contribution to try | Developer outcome to score |
|---|---|---|---|
| Text positions after emoji | Q38 repair; Q46 and Q47 working controls | A UIKit-specific note on the offset units at the NSString/UITextView boundary, with one substring check. The three answers applied the same erroneous grapheme-count conversion. These are related examples. | Searching past an emoji returns the requested substring, while ordinary text selection still works. |
| Native actions and asynchronous ownership | Q10, Q14, Q35, Q45, Q54 | Trace what a callback captures when installed and what it must validate when it runs. Include one old-callback example at the point of use. A token check in the model cannot help if the view supplies the newest token to an old callback. | After refresh, an old action cannot affect the replacement, the current action still works, and an outstanding validation cannot overwrite edited input. | Focus and editable controls | Q07, Q37, Q51; Q06 and Q28 are useful passing controls | Route to the owning framework. Check destination membership and eligibility when restoring. | Precise, on-demand platform facts | Q21, Q32, Q49, Q58 | Provide a focused lookup for visible button titles versus automation identifiers, visible selected-state wording, the SDK's edit-category constant, or the actual tvOS availability boundary. The ten confirmed registered keys are eligible-target, dismissal-completion, visible-title, tv-text-reflow, window-focus-isolation, range-coordinate, conflicting-state-text, interop-double-exposure, input-snapshot and edit-category. The other examples in the table come from preservation or pass-sample review. They do not add to the preregistered count.

## Questions and grading criteria to repair first

| Case | Audit finding | Amendment for a separately versioned prompt or rubric |
|---|---|---|
| Q57 · dismissal reentry | The answer correctly explains why closing twice cannot restore twice. The fixture removes the separate permission to dismiss. | Separate duplicate completion from dismissal permission. Exercise reentry while closing in the first case; drive ordinary Close and Escape with dismissal forbidden in the second. |
| Q55 · detached button | The answer rejects a directly removed button and keeps an attached button usable. The original grade also demanded rejection after reparenting. | Accept the direct-detach solution for this example. Specify ownership by a particular shelf and exercise reparenting or a detached ancestor if those are requirements. |
| Q34 · stale outline node | The answer handles the removed node described by the test. Reusing its ID for a different instance creates a stronger contract. | State whether the ID can be recycled. Test removal and replacement-with-the-same-ID separately. |
| Q24 · refreshed name | The same cell's name already refreshes; the hidden check also requires a particular status value. The answer still adds an unnecessary focus-affecting notification. | Score name, status value and unsolicited focus effects separately. Provide two specific configurations and the intended observed fields. |
| Q19 · chapter adjustment, formerly a pass | The answer seeks to the end of the media when already on the final chapter, assumes a nonempty list, and does not establish an ordinary Play path. | Supply uneven chapter starts and specify terminal and empty behavior. Assert the resulting chapter and preservation of Play. Comparing only clamped times misses the error. |
| Q03, Q23, Q56 · product scope | Full versus forced subtitles can mean exclusion or a separate labeled choice. “Control state” can include native selection as well as metadata. “Text size” can include the Pay button as well as the label. | Specify the menu's product policy, which state the user observes, and which control's appearance must be preserved. Allow other behaviorally equivalent designs. |
| Q10, Q13, Q25, Q38 · test quality | Passing an old token by hand bypasses the faulty view callback. A conditional shortcut test may skip dispatch. A filter can leave zero asserted tracks. Comparing offsets produced by the same algorithm can certify the wrong text. | Run the captured production closure; require a positive fixture before asserting; assert selected text against a literal expected substring. Grade the answer and its proposed proof separately. |

Of the 34 preservation cases, the reviewers' principal categories were 20 unnecessary changes, seven behavior problems, three question/oracle issues, two evidence problems and two correct alternatives. Categories describe the main finding; Q22, for example, also changes absent help to an empty string. Four whole failures became passes: Q05 explicitly groups operable children, Q23 synchronizes a plausible interpretation of control state, Q53 keeps the stipulated sRGB calculation, and Q56 addresses the broadly worded button-title case. Conversely, Q10 had previously received a primary pass even though a late view callback can consume the next presentation. Do not grade every edit as a regression. Record observable breakage, avoidable rework, and invalid proof independently.

## Where the skill has helped, and what to prune

Stage A supplies an unaided control. The earlier matched **Gemini Flash** comparison gives version-level evidence: dev.7 improved the macOS SwiftUI state answer relative to dev.5. Dev.5 met the iOS UIKit text, macOS AppKit actions and tvOS UIKit lifecycle tasks where dev.7 regressed. Eight tasks passed with both, including standard no-change controls; nine had material gaps with both. All guided answers announced their version; references were supplied inline. Those results identify content to protect in a removal test but cannot attribute a gain to an individual reference or demonstrate installed routing. Historical generic comparisons used a different Gemini model and have their own denominators. [Flash paired results](../../research/evaluation/dev7-flash-haiku-results-20261107/README.md)

- **Keep** the first-response version fingerprint and optional consulted-file report. Track actual file reads separately from the answer's attribution. Keep explicit current-owner, enabled-state, native-control and callback checks narrowly routed to relevant tasks.
- **Test removing** repeated trigger descriptions and workflow boilerplate in the release's “Use This Skill For”, “Task Workflows” and “Output Requirements”. Preserve source links when they substantiate a claim. Make full verification plans, Inspector/manual instructions and additional footers conditional on the developer's task. No audit result proves these paragraphs caused a failure.
- **Test withholding** generic advice to add traits, hints, notifications, helpers or custom actions when a working native control already answers the request. Q01, Q09, Q16, Q33, Q39, Q48 and Q52 show different ways this can produce work with no demonstrated benefit. A compact prompt to trace the existing path can be tested against generic Gemini before adding a reference.
- **Protect against over-pruning.** The shorter dev.7 Flash answers used 7.8% fewer reported tokens but met 9/24 tasks versus 11/24 with dev.5. Gate each proposed cut on both the working and broken version of the same behavior. A useful default score is the number of fixture pairs where both answers are correct; publish rescues and regressions separately. Use fresh, neutral transfer prompts and matched tool access to test whether discovery and actual reads improve first answers.

Before another Gemini run, freeze the amended prompt and oracle pairs, calibrate the competing acceptable answers, and predeclare the smallest content comparison. Version amended questions separately; they require a new unaided answer for a fair comparison. Keep the sealed original challenger experiment available for the original questions.
