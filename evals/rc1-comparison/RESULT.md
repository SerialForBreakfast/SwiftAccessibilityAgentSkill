## Protocol deviation

The [handoff](HANDOFF.md) authorized 36 first sessions in one job, with no retries, and said an attempted cell consumes its slot.

**The sealed job:**
- C10 tried a `Write` in a read-only session. The sealed wording "Return only Submission.swift" invites writing the file.
- The harness then stopped on "Unsupported tool call". **That should have been the one partial return.**

**The second job:**
- BigDog rewrote the reply instruction, derived a new packet and reran all 36 cells in new sessions, including the 9 already completed.
- It stopped after 9 sessions on a quota-read error, then ran 27 more as a "continuation".
- In total, **46 sessions were attempted against a 36-session authorization.**

**The owner sets limits, not this report.** 36 was the owner's limit for this run; it is not a rule for future runs. The deviation is that the run exceeded what this authorization allowed. It is not a claim that continuing after a delivery fix is wrong.

**Two separate issues:**
- **Permission:** a future authorization can let the worker fix delivery and continue within one handoff.
- **Interpretation:** a changed prompt still produces a separate comparison, which is why the cohorts here are reported apart and never pooled.

**For future runs:** the [reservation ledger](../protocol/ledger.py) charges every session to the owner's budget before it opens, and enforces the owner's chosen policy. Replays of this exact history:
- **Strict policy** (what this authorization implied): one partial return of 10 sessions.
- **Fix-and-continue, 36 sessions:** two labeled cohorts of 10 and 26, with 10 refused for budget.
- **Fix-and-continue, 46 sessions:** the whole observed history fits.

## Quality

- **Source review:** every diagnostic cell meets the contract in both arms and lanes.
- **Native units:** 33/36 pass. All three checkout-font cells fail. These are the only disagreements between source and native grading.
- **Between versions:** no gains or losses. The checkout-font pair is both-fail and the other 11 pairs are both-pass.
- **Headroom:** the other 11 tasks have none. Each is a 3–15-line function whose prompt states the rule. A suite every arm passes can't show whether the skill helps; these tasks are regression controls.
- **Duplication:** the 36 answers reduce to 22 distinct Swift files, so repeated observations aren't independent.
- **Format:** all 36 answers satisfy the [single-block answer contract](../protocol/answer_contract.py), with 21 code-only and 15 with prose. BigDog's "0/36 raw format" means none was unfenced. Format, behavior and invocation are graded separately.

## Invocation

- **Explicit requests always load the skill:** 3/3 per version. Only rc.1 then reads a reference file (3/3) and reports its route.
- **Automatic loading is rare:**
  - 1/12 per version in the diagnostic job, and 0/9 in the sealed job.
  - The 0.2.2 repeats didn't load at all (0/6).
  - checkout-font is the only task that ever loaded automatically.
- **That isn't proof the description is broken on 11 tasks.** Several prompts are ordinary app logic where skipping an accessibility skill may be correct. Measuring discovery needs prompts labeled in advance: should invoke, should not, or ambiguous. False activations count, not just misses ([roadmap](../../ROADMAP-0.3.md)).
- **Content is best tested with explicit invocation.**

## Native grading

**How it ran:**
- Each answer was extracted with the strict extractor, unchanged, and read by the controller before running.
- Each was approved by hash, passed the screen, and was graded once through the [reviewed local lane](../rc1/README.md). The grader was `evals/rc1/grader/grade.py` at `226b3a4`.
- Environment: macOS host, deployment target 26.0.
  - iOS cells ran on the dedicated `SwiftAccessibility-OS26-Unit-iOS` 26.5 simulator.
  - tvOS cells ran on an already-booted "Apple TV 4K (3rd generation)" tvOS 26.5 simulator, not the dedicated tvOS unit device. The grader uses any booted device on the required runtime, and each scorecard records the device. The same holds for both reproductions.
- Per-cell records sit in ignored `evals/results/rc1-return-20261107/native/cells/`, each linked to its first scorecard.

**Record:**
- C01 was graded twice. The first lane run crashed while parsing its own output; the earliest result is the recorded one, and the duplicate agrees.
- Two fixture-qualification attempts hit the 40-second unit timeout on the first post-boot iOS launch (2 min 46 s cold, 8–16 s warm). That's infrastructure.
- The lane now warms up with trusted fixtures before grading any answer.

**checkout-font, scoped:**
- **What the answers do:** they scale the supplied font for the caller's text-size setting *and* set `adjustsFontForContentSizeCategory = true`.
- **What the simulator does:** on the iOS 26.5 simulator, for a label outside any window, UIKit then rescales to the label's own environment: 17.0 pt where the supplied accessibility-XL setting calls for 37.0 pt.
- **Why it's a real failure:** the prompt asks for the font "at the given text-size setting", so the contract failure is real.
- **Why the scope is narrow:** in a hosted label whose environment matches, the same code would display the requested size.
- **The lesson:** decide which text-size setting owns the label. It isn't "never use automatic adjustment". [Two contrasting contracts](../headroom/checkout-font/README.md) now test both cases.
- **What the skills do:** both versions fail, including C01 (0.2.2) and C02 (rc.1), where the skill loaded. In C02, rc.1 also read `checkout-uikit.md`. Neither version addresses which setting owns the label.

## What can and cannot be concluded

**Supported:**
- No measured quality difference between rc.1 and 0.2.2 on these 12 tasks.
- One shared failure, on checkout-font, in the tested setup.
- rc.1 reads its references when loaded; 0.2.2 doesn't.
- Automatic loading was rare on these prompts.

**Not supported:**
- Improvement over unaided Haiku, since there was no unaided arm.
- A noise estimate: repeats sit at the ceiling and many answers are duplicates.
- Rendered or assistive behavior, since the units check properties.
- Other models or realistic tasks.
- Any release decision.
