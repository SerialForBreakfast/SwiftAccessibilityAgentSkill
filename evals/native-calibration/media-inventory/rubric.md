# Controller rubric: two addressable options

Development question derived from inspected media incidents; not held out or independently graded. Score the supplied current-load contract, not features from another picker.

- Inventory: two distinct native options with the same display or language key remain individually addressable. Load-scoped ordinal, opaque ID, or equivalent binding to distinct option objects is acceptable. Display strings can remain unchanged. No persistent ID requirement.
- Write: map the actual user choice to its option and write to the owning current item's legible group. A local selected ID alone is insufficient. Leave the audio selection and ordinary playback control alone.
- Verification: contrast Off or another initial native selection with the result after each choice. Inspect the actual item's caption and its independently established audio option. Fixture readiness is a prerequisite, not a correctness result.
- Evidence: distinguish a supplied-group test of the writer from a native asset load through the production inventory. A plan without execution is a plan; a passing native unit does not establish rendering, spoken output, language quality or user experience.
- Scope: this menu explicitly offers all subtitle options. A complete-captions-only product can have a different filtering policy. Do not enforce a particular UUID, ordering, generated label, type name, test library or second menu.

The native controller checks the underlying behavior, not the exact starter's type names. It separately challenges identity collisions, omitted writes and unrelated audio mutations. A future answer with a different API needs an audited binding before it can be assigned a native grade.
