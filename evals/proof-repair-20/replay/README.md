# Preserved proof replay

This is retrospective mutation testing, not a new model comparison. A proof unit is the complete submitted Swift Markdown block, including all its test methods. Identical bytes shared by several answers are replayed once per applicable production owner. A neighboring task about the same component may correctly leave the selected defect undetected; do not interpret this benchmark as a regrade of that original answer.

## Scope and isolation

Inventory enumerates answer-bearing project ZIPs on the existing private share, including original/continuation records and original answers embedded in the dev.7 JSON. Exact answer hashes, archive member names, block offsets, and proof hashes are recorded privately. Only Swift or unlabeled fenced blocks, or entirely unfenced Swift answers beginning with an import, are extracted. Match the concrete production owner targeted by the supplied defect, not every type in a multi-feature file. This bounds the search: prose, unbound pseudocode, tests for another owner, and tests that never name a subject type are not executable evidence for this board. This is not a claim that all historical model output in other accounts or chats is available.

No edits to submitted Swift. The native harness supplies XCTest, platform and testable product imports; a named placeholder module is bound to the original production sources. A standalone test method can be enclosed in a discovery class. These accommodations establish behavior under the recorded harness, **not** standalone buildability of the answer. The wrapper contains the exact original block; production declarations are never synthesized to make tests pass. Each submission gets a distinct test target. Each fixture variant uses the qualified production files; the original weak test and author qualification tests are not mixed in.

## Interpretation

- **Catches defect**: same discovered methods pass on working and alternate code; the defective variant fails a submitted assertion on the affected behavior.
- **Misses defect**: all three pass. This describes sensitivity to this particular defect, not general answer quality.
- **Rejects valid code**: an assertion fails on a qualified valid implementation; not a successful discriminator even if the defect also fails.
- **Gap**: the proof cannot bind, methods are missing/skipped, or the failure cannot be attributed. A compile error or crash is never counted as a catch.

Inputs, first compiler diagnostics, wrapper files, native logs, structured results, and the private provenance join are retained under the repository's ignored evaluation results directory. The per-proof public board uses hash IDs. No historical grading, model answer, installed skill, or qualification triplet is rewritten.

[Per-case and per-submission results](RESULTS.md). Of 198 matched blocks, 179 were executed on each of three implementations (537 proof-block/variant observations, not 537 independent questions); 19 did not compile unchanged under the supplied harness. Four Swift Testing submissions initially hit a missing macro loader in preflight and were recovered by loading the installed plugin. Their original diagnostics remain in the private record. One Mac Save test threw an Objective-C exception dispatching a missing selector: although it separated the variants, it is **not** counted as a behavioral assertion. Crashes and that exception are shown separately from compiler incompatibilities. No compatible replay remains pending in this inventory.
