# Grade decisions, not resemblance to the reference

Grade the exact question and supplied input before opening the other arm, old answers or grades. For each decision record pass, material fail, or unresolved, with the decisive answer excerpt, the concrete user consequence and the input that distinguishes a wrong answer. The controller gives the requested observable and a counterexample, not required wording. Accept alternative implementations and good no-change answers. The origin IDs are evidence of a hazard, not grades for this question. Where platform differs from an ancestor, use platform-appropriate public declarations, not an imported assumption.

For design/architecture require a workable owner and preserved interaction, not compilable code. For triage require discriminating observations rather than certainty; allow multiple plausible diagnoses. For patch review grade the actual delta direction. For code review follow the real caller, inputs and unchanged actions. For test design/acceptance grade initial conditions, triggering path and expected observable separately: a helper-only test, a silently missing fixture, or a test that passes the defective version cannot establish integration. Accept equivalent witnesses. Source review of examples is not proof that arbitrary submitted code runs.

Separately record: primary accessibility decision; ordinary-action preservation; integration; production build; submitted test build; discriminating proof; unnecessary changes; whole task. Use not-applicable for unrequested code, not-run for unexecuted proofs, harness-gap for binding/setup failures. Freeze all original answers and judgments. Grade native behavior only on a compatible qualified contract; a mutant that compiles is not a killed mutant. A new critical action/navigation loss is visible independent of averages.

A **rescue** requires unaided fail AND skill pass on identical inputs with matched settings/tools and the same grade. Also report losses, persistent failures, preserved successes and inconclusives. Count net and gross, by distinct decision family as well as question; cluster variants sharing a source, not 500 independent trials. A rescue on a known development case is not independent transfer. Keep a separate stratified sample of original passes to detect regressions. Never select prompts for reporting based on seeing both arms' answers.

For local paired reporting use score.py with private JSONL records containing id, arm (unaided or skill), promptSHA256, modelRevision, transport, settingsSHA256, permissionsSHA256, rubricSHA256, decision, whole and ordinary. Use pass/fail/unresolved for these three summary fields; for ordinary use unresolved when not applicable (retain that distinction in the detailed record). Missing or incompatible pairs have their own denominator. Preserve detailed excerpts and evidence separately. A primary-decision rescue without a whole-task rescue is not a successful complete answer.
