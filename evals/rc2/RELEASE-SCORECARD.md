# Release scorecard: 0.3.0-rc.2

**Decision, November 13, 2026: keep 0.2.2 as the default; keep rc.2 opt-in.** All three corrections have offline checks. **None of the three has a direct rc.2 vs 0.2.2 model result.** The six caption-picker and two sheet-dismissal questions in the [eight-pair comparison](../rc2-starter-comparison/results/README.md) were a stress test, not a test of these corrections: 0.2.2 passed **3/8**, rc.2 **1/8** (zero gains, two regressions). One loss was an unbuildable picker; the other was a correct sheet fix with an unbuildable test.

| Change and developer decision | User impact | Direct test and existing evidence | What must keep working | Still unmeasured |
|---|---|---|---|---|
| **Mac search** (`P-d82c`): Which layer owns the duplicate “Search” stop? Remove redundant wrapper semantics, not the hosted editor. | Someone navigating with VoiceOver must still reach the field where they can edit the query. | The macOS unit checked that the native field is editable and selectable, accepts a value, and retains its label. The fixture wiring check accepted hiding decorative artwork beside the field and rejected hiding the representable itself. | Native text entry, selection and insertion; legitimate hiding of decorative siblings. | Whether rc.2 recommends the safe fix more often. These checks did not count VoiceOver stops or exercise an editing session. |
| **Ordinary tap-to-play** (`P-f93b`): Add chapter adjustment without moving playback off the existing single tap. | A person can still tap to play or pause; someone using accessibility adjustment can change chapters without toggling playback. | The unit invoked tap, increment, tap and checked playback and chapter independently. The wiring check accepted two single-tap forms and rejected an accessibility action substituted for the tap. | Single tap on the original surface, chapter adjustment, and existing drag-to-seek. | Whether rc.2 preserves all three in a developer answer. Neither physical gesture delivery nor tap/drag arbitration was tested. |
| **Media inspector** (`P-9c45`): How should a test distinguish no player item from a loaded item without an audio group? Match the returned cases; the track payload need not support equality. | A developer can ship a buildable inspector that distinguishes “nothing to inspect yet” from “this item has no audio options.” | The macOS unit inspected nil and a real item backed by an empty composition. Mapping both to absent failed the unit. Synthesizing equality for an enum with a nonconforming payload failed compilation as expected. | The distinction between the two empty states and the existing loaded payload. Genuine equality remains a valid alternative when the types support it. | Whether rc.2 produces buildable answers on this decision more often. These particular units did not exercise a populated group; picker tests are not inspector tests. |

**Delivery, scored separately:** The quoted YAML description fixed a real discovery failure: skills CLI 1.5.4 installed rc.2 project-locally and the files matched the archive. The entry point routes search/tap to Actions and inspector results to Media. Link and package checks establish that those cards are available, not that an agent selects or applies them correctly on these tasks. [Package and installation evidence](README.md) · [Swift assertions](checks/Contracts.swift) · [Wiring and compiler checks](checks/verify.py)

**Next decision:** Before another run, freeze one fresh developer task per decision above, paired with a working implementation that should be preserved. Grade the accessibility decision and the buildability of the submitted change **separately**. A passing helper test should not offset a hidden editor, a missing tap, or an inspector that does not compile.
